==================================================
1) OBJETIVO GENERAL DEL SISTEMA
==================================================

Crear y mantener una plataforma web para la **gestión administrativa del servicio de agua potable y alcantarillado**, que permita:

- Registrar y consultar **afiliados** (titulares del servicio).
- Gestionar **pagos mensuales** (agua + alcantarillado).
- Registrar y cobrar **multas**.
- Gestionar **trámites** (cambio de titular / nombre).
- Generar **reportes** de recaudación y deudas.
- Administrar **usuarios del sistema** con roles y permisos.
- Ofrecer un **panel** con indicadores resumidos.

El sistema es de uso interno (oficina/caja), no es un portal público para afiliados.

3) REGLAS DE NEGOCIO CLAVE
==================================================

Tarifas mensuales fijas (modelo `Pago`):
- Agua potable: **Bs 8.00** (`Pago::MONTO_AGUA`)
- Alcantarillado: **Bs 15.00** (`Pago::MONTO_ALCANTARILLADO`)
- Total por período: **Bs 23.00**

Afiliado:
- CI, nombres, apellidos, teléfono, dirección, fecha de afiliación, estado (activo/inactivo).

Pagos:
- Por mes/año por afiliado.
- Estados: pendiente / pagado.
- Generación masiva de cuotas del mes.
- Número de recibo.

Multas:
- Registro y marcado como pagada.

Trámites:
- Cambio de titular (CI, nombres, apellidos nuevos).
- Verificación de deudas antes de tramitar.
- Estados: pendiente; aprobación/rechazo solo con permiso `tramites.aprobar`.

Autenticación:
- **No existe registro público** (`Features::registration()` deshabilitado en `config/fortify.php`).
- Nuevos usuarios solo los crea/edita un **administrador** en Gestión de usuarios.
- Página Welcome: solo "Iniciar sesión", sin botón Registrarse.

==================================================
4) ROLES Y PERMISOS
==================================================

Roles (`app/Models/Role.php`):
- `admin` — acceso total.
- `cajera` — operación diaria (sin gestión completa de afiliados, sin aprobar trámites, sin reporte de deudas, sin gestión de usuarios).
- `operador` — legado; misma lógica que cajera.

Permisos (`app/Enums/Permission.php`):
- panel.ver
- afiliados.ver / afiliados.gestionar
- pagos.ver / pagos.gestionar
- multas.ver / multas.gestionar
- tramites.ver / tramites.gestionar / tramites.aprobar
- reportes.ver / reportes.deudas
- usuarios.gestionar (solo admin)

Middleware en rutas: `auth`, `verified`, `role:admin,cajera,operador`, `permission:...`

Frontend: composable `usePermissions()` — `can()`, `hasRole()`, `isAdmin`.

Sidebar (`AppSidebar.vue`): filtrar ítems por permiso.

Tras cambios en permisos ejecutar:
```bash
php artisan isinuta:sync-roles
```

6) ARQUITECTURA Y CONVENCIONES DE CÓDIGO
==================================================

Estructura Laravel estándar + Inertia:
- Controladores delgados; validación en Form Requests.
- Políticas/middleware para autorización.
- Factories para tests.
- Páginas Vue en `resources/js/pages/` con **un solo elemento raíz**.
- Layout del panel: `AppSidebarLayout` / `AppLayout` (no duplicar sidebar en cada página).
- `app.ts`: layout global solo para settings; páginas del panel definen su propio layout.

Wayfinder:
- Importar rutas desde `@/routes` y acciones desde `@/actions`.
- Usar `.url()`, `.get()`, `.post()`, `.form()` según corresponda.
- Tras nuevas rutas: regenerar con el flujo del proyecto (`npm run build` o dev).

UI/UX:
- Tema claro por defecto; clases utilitarias `isinuta-*` en `resources/css/app.css`.
- Diseño responsive (móvil y escritorio).
- Mensajes flash con `FlashBanner`.
- Búsquedas con debounce en listados.

PHP:
- Tipos de retorno explícitos, constructor property promotion, enums TitleCase.
- PHPDoc en métodos no obvios.

**Prohibido:**
- Sustituir masivamente etiquetas HTML (errores históricos con tags `motion` inválidos).
- Crear scripts de verificación ad-hoc si ya hay tests Pest.
- Documentación `.md` no solicitada.
- Commits o cambios de dependencias sin pedirlo.
